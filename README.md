# Zabbix Action Audit

Аудит действий триггеров Zabbix (6.0 LTS – 7.4). По каждому действию показывает:

- под какие триггеры (`potential`) и текущие проблемы (`active`) оно попадает;
- дойдёт ли уведомление до каждого получателя, и если нет — почему: отключён пользователь, нет прав на хост,
  проблему скрывают tag-фильтры, нет медиа нужного типа, медиа/тип медиа отключены, важность не включена в медиа и т.д.

Техзадание и архитектура: [docs/TZ.md](docs/TZ.md).

## Запуск

```bash
pip install -e .            # или без установки: python3 -m zabbix_action_audit ...
zabbix-action-audit -o reports/audit.html                 # HTML, оба режима
zabbix-action-audit --mode active --format text           # только текущие проблемы, в консоль
zabbix-action-audit --action "all problems to tg" --uncovered -o audit.html
zabbix-action-audit --dump-snapshot snap.json -o a.html   # сохранить выгрузку API
zabbix-action-audit --from-snapshot snap.json -o a.html   # аудит офлайн по выгрузке
```

## Флаги запуска

### Источник данных

| Флаг | По умолчанию | Описание |
|---|---|---|
| `--secrets FILE` | `secrets.txt` | Файл с URL и токеном (`Zabbix_url: …`, `Zabbix token: …`, опционально `Zabbix verify ssl: …`) |
| `--url URL` | из `ZABBIX_URL` / файла | Адрес фронтенда Zabbix (`http://zabbix/`) или полный путь к `api_jsonrpc.php` |
| `--token TOKEN` | из `ZABBIX_TOKEN` / файла | API-токен. Лучше передавать через переменную или файл: аргумент виден в списке процессов |
| `--no-verify-ssl` | проверка включена | Не проверять TLS-сертификат. Несовместим с `--ca-bundle` |
| `--ca-bundle FILE` | системные CA | Проверять сертификат по своему CA (PEM), например для внутреннего УЦ |
| `--timeout SEC` | `120` | Таймаут одного запроса к API в секундах |
| `--chunk-size N` | `100` | Сколько хостов запрашивать за раз в тяжёлых запросах (хосты, триггеры, макросы, проблемы). При ошибке 5xx или таймауте порция сама делится пополам; если это происходит часто, уменьшите значение |
| `--dump-snapshot FILE` | — | Сохранить выгрузку из API в JSON, чтобы потом повторять аудит без нагрузки на Zabbix |
| `--from-snapshot FILE` | — | Провести аудит по сохранённой выгрузке, без обращения к API |

### Аудит

| Флаг | По умолчанию | Описание |
|---|---|---|
| `--mode potential\|active\|both` | `both` | `potential` — все включённые триггеры («что может прийти»), `active` — текущие проблемы («что должно было прийти сейчас») |
| `--action ID\|NAME` | все действия | Проверить только указанные действия; флаг можно повторять. Если в условиях действия есть «Группа узлов =» или «Узел =», загружаются только подходящие хосты — это сильно снижает нагрузку на крупных инсталляциях |
| `--skip-disabled` | отключённые включены | Не показывать отключённые действия. Их ошибки и так не влияют на код возврата |
| `--uncovered` | выключено | Добавить список триггеров и проблем, которые не подпадают ни под одно включённое действие с отправкой сообщений. Требует загрузки всех хостов, даже вместе с `--action` |
| `--tz ZONE` | часовой пояс машины | Часовой пояс сервера Zabbix (`Europe/Moscow`) для условий «Период времени» и периодов активности медиа |

### Отчёт

| Флаг | По умолчанию | Описание |
|---|---|---|
| `-o, --output FILE` | stdout | Куда записать отчёт |
| `--format text\|json\|html` | по расширению `-o` | `html` для `*.html`, `json` для `*.json`, иначе `text` |
| `-v` / `-vv` | только ошибки | `-v` — ход загрузки (сколько хостов и триггеров, порции, повторы), `-vv` — каждый запрос к API с временем и размером ответа |

Для первого запуска на крупной инсталляции:

```bash
zabbix-action-audit -v --action "Имя действия" --mode potential --chunk-size 20 -o reports/one.html
```

## Подключение и TLS

Подключение: `secrets.txt` (`Zabbix_url: …`, `Zabbix token: …`), переменные `ZABBIX_URL` / `ZABBIX_TOKEN`
или `--url` / `--token`. Нужен токен Super admin: аудит только читает API.

Проверка TLS-сертификата (приоритет: аргумент > переменная > файл):

| Что нужно | Аргумент | Переменная | Строка в `secrets.txt` |
|---|---|---|---|
| не проверять сертификат | `--no-verify-ssl` | `ZABBIX_VERIFY_SSL=false` | `Zabbix verify ssl: false` |
| проверять по своему CA | `--ca-bundle ca.pem` | `ZABBIX_VERIFY_SSL=/path/ca.pem` | `Zabbix verify ssl: /path/ca.pem` |

Для внутреннего УЦ лучше указать его сертификат, чем отключать проверку.

## Результат

Коды возврата: `0` — нет FAIL во включённых действиях, `1` — есть FAIL, `2` — ошибка выполнения.

«Не определено» означает, что результат зависит от того, что известно только в момент события: период времени,
подавление, макросы вроде `{ITEM.LASTVALUE}` в имени или тегах. Такие триггеры показаны отдельно.

## Тесты

```bash
python3 -m pytest                       # юнит-тесты, без сети
python3 -m pytest -m integration        # на живых стендах
```

Интеграционные стенды:

- `local` — Zabbix из `secrets.txt`;
- `zbx60` — одноразовый 6.0 LTS: `docker compose -f tests/zabbix60/docker-compose.yml up -d`
  (`down`, чтобы удалить; база в tmpfs).

Выбор стендов: `ZAA_STANDS=local,zbx60`. Тесты создают объекты `zaa-test-*` и удаляют их после себя
(остатки прерванного запуска удаляются при следующем). Тестовые проблемы генерируются только если ни одно
существующее включённое действие стенда не отправит по ним уведомления.
